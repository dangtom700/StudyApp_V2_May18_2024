April 2026 Update

Comprehensive breakdown of features, architectures, and new workflows for the StudyApp PDF Manager.

🧠 Semantic Search Engine

Python LangChain Ollama Chroma Vector DB

We completely overhauled the search logic. Instead of relying solely on exact keyword matches, the system now understands the meaning behind queries using local AI models.

The Process:

  • Ingestion Bypassing: Text chunks are streamed directly from the SQLite database into the Chroma Vector Store inside src/embed.py, skipping redundant intermediate text-splitting loops.
  • Parallel Processing: Batching algorithms handle bulk insertions, cutting down indexing times significantly.
  • Semantic Routing: User queries from the PyQt5 UI are embedded using local LangChain pipelines via Ollama, pulling mathematically similar conceptual chunks rather than explicit string matches.

📄 Native PDF Rendering & UI Upgrade

Python PyQt5 PyMuPDF

The PDF Viewer Tab has transformed from a simple text previewer into a fully-fledged reading suite.

The Process:

  • Actual Document Rendering: Integrated PyMuPDF (fitz) to process the raw PDF files dynamically inside the UI instead of rendering stripped `.txt` versions.
  • Responsive Split-View: The app calculating the aspect ratio of the rendered document and utilizes an auto-fit width layout so the document adjusts optimally to any screen size.
  • Contextual Sidebars: While reading, a new side-panel performs live lookups into the Item Matrix, offering immediate serendipitous recommendations based on the current document.

⚙️ Core Pipeline Resiliency

C++ SQLite3

Handling thousands of documents computationally can take hours. The core NLP engine written in C++ (feature.hpp) now features stateful awareness.

The Process:

  • Resumption Logic: The label_topics and mappingItemMatrix routines now map current progress via per-topic ID filtering. If execution drops, the pipeline reads the highest completed iteration and safely resumes without recomputing existing work.
  • Topic-to-Topic Similarity: Introduced an experimental --TopicSimilarity feature that automatically compares topic pairs, computing and storing their relational distances in the database using efficient, bidirectionally inserted scores.
  • Bidirectional Query Fixes: Upgraded the recommendation engine to fetch unique IDs using advanced SQL mapping for the `comparison` table, correcting the A-B / B-A duplication bug when analyzing the "shrinking pool" datasets.
  • Decoupled Tokenization: Removed the hard dependency on `wikipedia_api`. The `tokenize_topics` pipeline now utilizes local wiki articles formatted within the wiki_topics directory.

🚀 New Workflow Walkthrough

Experience the updated architecture by following these steps:

1
Re-build your Envs
Due to the addition of LangChain, Chroma, and PyMuPDF, ensure you update your environments. Run conda env update -f app/env.yml.
2
Populate Vector Store
In your terminal, execute the ingestion script via python src/embed.py to initialize your vector store based on existing sqlite data. This utilizes parallel batching.
3
Launch the Application
Run run_app.bat (Windows) or bash run_app.sh (Mac/Linux).
4
Experience the Magic
Head to the PDF Viewer tab. Select a document. Notice the high-fidelity rendering. Click on the sidebar to instantly navigate to conceptually dissimilar files powered by your newly baked semantic engine!
